# Архитектура stage 1

Репозиторий и есть лаборатория. Отдельный каталог `crypto-trading-lab/` не вложен: клон `max_trade` сразу содержит конфиги, стратегию и оператор.

## Граница с Freqtrade

Freqtrade 2026.10 в образе `freqtradeorg/freqtrade:2026.10` исполняет бэктест, скачивает OHLCV, ведёт SQLite и отдаёт FreqUI. Код лаборатории не копирует движок и не считает сделки заново.

Свой код делает четыре вещи:

- собирает конфиг, в котором live-поля стёрты;
- не пускает контейнер, если конфиг после сборки кто-то поправил вручную;
- проверяет скачанные свечи и сравнивает два архива бэктеста;
- даёт одну команду `labctl` на управление контейнером с ПК.

Образ зафиксирован тегом релиза. Тег `stable` для этой сборки не используется: он двигается отдельно от проверенного набора команд.

## Поток данных

`labctl` читает `.env`, записывает `user_data/config.active.json` и вызывает `docker compose`. Контейнер монтирует `strategies/` в каталог стратегий Freqtrade. Точка входа `scripts/entrypoint.sh` ещё раз запускает preflight и только потом `exec freqtrade`.

Для команды `trade` preflight требует локальные пароль API, JWT и WebSocket-токен. Для `download-data` и `backtesting` достаточно безопасного режима: `dry_run=true`, `trading_mode=spot`, пустые ключи, whitelist из BTC/USDT и ETH/USDT, API на `127.0.0.1`.

Ключи биржи вырезаются при каждой сборке конфига. Публичные свечи и dry-run в них не нуждаются.

## Торговые ограничения сборки

- Только spot. `margin_mode` пустой, `can_short` выключен, усреднение позиции выключено.
- Депозит пробного прогона 1000 USDT, ставка 100 USDT, не больше двух позиций.
- Комиссия 0,001 на сторону записана в конфиг и ещё раз передаётся в команду бэктеста. Это допущение для сравнимых прогонов, не тариф, прочитанный с аккаунта.
- `use_order_book=false`. На истории стакана нет, поэтому проба не делает вид, что моделирует спред. Более жёсткая цена исполнения остаётся отдельным прогоном с большей комиссией на следующем этапе.
- Контейнер стартует с `initial_state=stopped`. Виртуальные входы начинаются только после `lab start`.
- `restart: "no"`. После перезагрузки ПК контейнер сам не поднимается. Для первой сборки это сознательно: длинный crash-loop на игровом компьютере хуже явной команды `lab up`.

## Свечи

Загрузка идёт командой Freqtrade `download-data` с `--trading-mode spot` и форматом feather. Проверка ряда отдельно смотрит дубликаты, порядок, сетку времени, знак цен и согласованность OHLC. Дырки остаются дырками и печатаются предупреждением: у биржи бывают реальные паузы, а подставлять цены нельзя. Файл без таймзоны UTC для feather считается ошибкой.

Окно `20240101-20240301` нужно только для парного прогона. Перед ним в ряде должны лежать свечи прогрева EMA 200. Полная загрузка с `20200101-` это закрывает, если биржа отдаёт историю.

## Повторяемость

Freqtrade пишет zip. Внутри отчёта поля `run_id`, `backtest_start_time` и `backtest_end_time` — это часы запуска, они снимаются перед сравнением. Сделки, цены и идентификаторы заявок бэктеста остаются. Сухой прогон использует случайные id заявок, поэтому повторяемость проверяется на бэктесте, а не на dry-run.

Рядом пишется `user_data/reproducibility.json`: совпали ли прогоны, число сделок, окно, хеши файлов свечей и прямая оговорка, что это не оценка доходности. Каталог результата в git не входит.

## Оператор на ПК

`scripts/lab.sh` и `scripts/lab.ps1` вызывают `scripts/labctl.py`. Это и есть управляющая программа на компьютере. Она ходит в API контейнера на `127.0.0.1` командами start, pause и stop. Пароль читается из `.env` и в лог команды не пишется.

Облачный агент этот ПК не видит. Чтобы управлять лабораторией с компьютера, репозиторий открывается в Cursor уже там, и локальный агент вызывает `./scripts/lab.sh`.

## Что сознательно не входит в stage 1

Пять боевых стратегий, детектор режима, отдельный риск-модуль, walk-forward, PostgreSQL, FastAPI, Telegram, Prometheus и Grafana. Их рано добавлять, пока на ПК нет двух совпавших бэктестов по реальным свечам.
